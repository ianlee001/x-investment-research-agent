## 一、项目整体介绍

### 1.1 项目概述

**X 投资观点研究助手是一个面向个人美股研究场景的 AI 应用。用户关注公开 X 账号，在包含生活、转帖和投资内容的混合帖子中选择一条具体投资观点，系统调用行情、公司披露和 Web 资料，将观点组织为断言、支持与反对证据、来源片段和不确定性，供用户复核和继续研究。**

项目的核心不是预测股价或替用户交易，而是把“看到一条观点后，需要反复搜索、对照资料”的过程组织为可追溯的研究任务。它包含已部署到个人 VPS 的全栈 MVP、Agent 工具与运行控制、持久化和人工审批，以及 PRD、交互原型、评估方案和界面迭代材料。

### 1.3 背景、用户和核心问题

动机来自本人阅读 X 美股内容的经历：关注的博主可能谈论 MU（美光科技）、科技股或存储周期，并预测未来上涨。本人想核对行情、权威新闻和公司披露，了解观点中哪些部分有证据、哪些只是预测或情绪表达。最麻烦的是跨站查找资料，并把资料与原帖中的具体说法对应起来。

目标用户是会阅读公开投资观点、希望自行形成研究判断的个人阅读者。真实需求和验证来自本人；“证据核对型个人研究者”“持续跟踪型阅读者”是产品材料中的任务画像，不能写成已经验证的人群规模或真实招募结果。

核心问题有五个：

1. 一个账号的内容是混合的，系统不能把每条帖子都当投资观点，也不应默认全部发起付费核查。
2. 一段话常混合事实、未来预测、个人意见和推论，需要分开评价。
3. 搜到一篇文章不代表它支持该主张；主体、指标、时期、单位、比较基准和反向证据都影响判断。
4. 研究需要等待和多次工具调用，刷新、断线、取消、供应商失败或进程重启时，应保留清楚的任务状态和已有资料。
5. Agent 可以提出保存观点、修改偏好等动作，但不能把模型提议直接当作用户授权或执行成功。

“多数博主这样说”不是本项目的事实证明方法。多人意见一致至多表达观点分布，不能代替外部证据，也不构成独立信源数量。

### 1.4 核心主线与整体方案

```text
关注公开 X 账号
  → 同步并浏览混合帖子
  → 用户选择一条具体投资观点，点击核查
  → FastAPI 建立持久 Run，独立 Worker 执行
  → Qwen 在 LangChain 单 Agent 中选择受限读工具
      ├─ X：原帖与已追踪帖子，作为研究线索
      ├─ Massive：上一交易日行情、复权日线、公司资料
      ├─ SEC：公司披露、标准财务概念、申报文件片段
      └─ Tavily：Web 搜索与页面抽取
  → 保存本次 Source，生成结构化断言和证据关系
  → 代码检查来源归属、引文定位及保守状态规则
  → 阅读报告、双向证据、来源、时期单位和不确定性
  → 在研究对话中继续提问

Chat 中涉及个人资料写入：
  模型提议 → HITL 暂停 → 人工批准 / 编辑 / 拒绝
  → 以原 checkpoint 恢复 → 执行边界再次校验 → 保存实际执行结果
```

当前报告包含追问文本，用户可以进入研究对话继续研究；**从报告一键携带结构化上下文到对话是 V1.1 目标设计，不能写成现有功能。**

## 二、实际工作与实现

<a id="m01"></a>
### M01｜业务建模、需求与产品范围

- **做了什么：**围绕“单条公开投资观点核查”定义账号、Post、Claim、Source、Evidence、Run、Approval 等对象，将用户任务拆成 12 组需求与验收组。
- **为什么：**核查必须有明确对象、证据关系和完成信号；不能把“生成一篇看起来专业的报告”作为唯一成功标准。
- **方法与选择：**按任务必要性、错误后果、使用频率与实现依赖判断优先级；P0 闭合核查与避免误导，P1 支持持续研究，P2 扩展图片、周报与外部推送。未用缺少真实样本的 RICE 分数制造量化结论。
- **具体产出：**PRD 包括字段长度与枚举、时间与单位、页面状态、错误、预算、审批和验收；需求、页面、用例及实现差异有对应关系。
- **研究材料：**已有任务型竞品分析、画像、旅程、研究提纲和演示编码；竞品依据当时登记的官方资料，未进行同题付费对比实验。四个访谈角色为 SIM-R。
- **本人承担：**C01/C02/C04；提出问题与主流程、判断范围、通过 AI 协作形成完整材料。没有开展真实外部访谈的证据。
- **证据：**E01、E02、E13、E14。**属性：**USER + DESIGN；核心范围同时有 IMPL。

<a id="m02"></a>
### M02｜公开 X 账号、混合帖子与增量同步

- **做了什么：**添加/移除公开账号，读取官方账号与时间线，保存混合文本帖子，按账号、cashtag、核查状态筛选；用户对具体帖子点击“核查观点”。
- **为什么：**生活帖与投资帖共存，保留选择权可以避免无关研究和额外调用。采集错误不能导致新帖子被永久跳过。
- **方法与实现：**`XProvider` 调用固定 X REST 路径；ID 全程保留字符串，长文优先用 `note_tweet.text`，保存发布时间、互动指标、引用关系及编辑历史 ID；cashtag 用正则提取。
- **关键选择：**初次回填有界；增量保存固定下界、分页 token 和 newest。只有完整处理本轮增量后才推进 `since_id`；部分响应出错不推进完成水位，通过 post_id upsert 去重。账号级 advisory lock 避免并行同步。
- **内容生命周期：**后台复核原帖可用性；不可访问内容会触发保守撤回，清理相关报告、引用、事件和 checkpoint。新研究入口拒绝不可用或超过 24 小时未核对的帖子，不声称实时监控删除。
- **结果：**历史真实样例将公开 `@nvidia` 的 5 条帖子入库并展示；增量水位、部分错误、长文 ID 和撤回有测试。初次真实样例为一页 5 条，不是采集规模成绩。
- **本人承担：**C01/C03/C05；确定混合帖子与手动核查流程，使用 AI 协作落地并进行个人自测。
- **证据：**E03、E10、E11、E17。**属性：**IMPL + ACT-REC + ACT-LOCAL；图片理解不在当前采集/模型链路中。

<a id="m03"></a>
### M03｜Agent、受限工具和多来源取证

- **做了什么：**一个 LangChain `create_agent` 驱动模型/工具循环，研究使用 `ToolStrategy(ReportDraft)`，对话使用普通回答并可提议个人写入。
- **为什么：**X 文本需要拆分和组织，财务、行情、新闻的依据应由相应外部工具提供；权限和结果格式不能只靠模型自觉。
- **模型：**`ChatOpenAI` 对接 DashScope 兼容接口，默认模型配置 `qwen-plus`；模型负责理解、选工具与组织，不是行情数据库或事实权威。实际配置可能由环境覆盖，不能仅凭默认值断言每次真实运行的具体型号。
- **MCP：**本地 `FastMCP` 暴露 9 个业务读工具，分别覆盖 Massive 行情/历史/公司资料、SEC 披露/指标/原文、X 已追踪帖子/单帖/可选近期搜索。`MCPAdapter` 管理工具发现和生命周期；Tavily 官方远程 MCP 只纳入 search/extract。X 搜索默认关闭，不是全档案搜索。
- **本地上下文：**两个本地读工具读取关注、偏好、观点与最近同 ticker 的历史研究；历史报告明确不能代替新鲜外部证据。Chat 额外开放四个敏感写工具，research 不开放。
- **Runtime：**`RunContext(run_id, user_id)` 与 `ToolRuntime` 注入运行归属、tool_call_id 和 Store，不让模型通过可见参数自行填写身份或审批状态。
- **具体边界：**本项目使用 Massive API key + 本地 REST 封装，不是 Massive 托管 MCP OAuth；没有多 Agent、自定义重复编排图、RAG、Embedding、向量库、MinerU 或 OSS。
- **本人承担：**C02/C03；确定证据研究范围并在 AI Coding 协作中完成数据源接入、联调和工具权限方案，不包装为自研基础模型或协议。
- **证据：**E04、E05、E10。**属性：**IMPL + 受限 ACT-REC。

### M04｜结构化断言、证据链与保守报告规则

- **做了什么：**把报告保存为摘要、整体判断、断言、正反因素、不确定性、追问、来源和信息截止日；Claim/Evidence 另存规范化业务表支持查询。
- **为什么：**用户需要找到“哪一条主张由哪段资料支持或反对”，而不是只读完整摘要；真实链接与正确语义是不同评价对象。
- **结构化方法：**Pydantic 定义 `fact / prediction / opinion / inference`；证据方向为 `support / contradict / context`。提示优先不超过 6 条关键断言，schema 最多 12 条，每条最多 8 项证据。
- **来源登记：**在工具结果交给模型前保存 Source；source_id 由 run_id、URL 与片段 hash 生成。模型引用程序分配的 ID；模型收到的截断片段与入库片段一致。
- **确定性校验：**检查 source_id 属于本次研究；规范空白后，quote 必须是 excerpt 的子串；按 source_id/方向去重；伪造来源或引文移除并产生警告。
- **状态控制：**X 不计为事实核验来源；预测和意见归 `not_verifiable`；同时存在非 X 支持与反对时归 `conflicting`；缺少对应方向证据时不能保留相应确定结论；推论不会保持完全 supported。
- **结果与边界：**真实受限 NVDA 报告有 3 条断言、4 个来源、0 引文定位警告。`assess_claim` 不判断语义蕴含、时期单位是否匹配，也不计算校准概率；同域/同 hash 统计不证明信源独立。
- **本人承担：**C01/C02/C03/C04；确定报告阅读与证据要求，在 AI 协作中将规则实现、评估维度和材料对应起来。不能将模型 stance 视为经过独立语义认证。
- **证据：**E06、E10、E14、E17。**属性：**IMPL + ACT-REC + ACT-LOCAL。

<a id="m05"></a>
### M05｜异步任务、SSE 与持久化恢复

- **做了什么：**FastAPI 提交持久 Run，独立 Worker 从 PostgreSQL 取队列任务，RunEvent 保存活动；前端通过 SSE 与查询展示状态、文本增量及结果。
- **为什么：**运行时间超过一次普通请求，不能让浏览器连接拥有执行生命周期；刷新、断线和重启后仍应能说明任务在哪一步。
- **状态设计：**`queued / running / awaiting_approval / completed / partial / failed / cancelled / expired`；Run、审批决定与工具实际执行不是同一个状态字段。
- **执行恢复：**启动时将遗留 running 重新排队；同 checkpoint thread 读取图状态，使用唯一 `user:<run_id>` 消息 ID 避免重复追加输入；有 resume 时走 `Command(resume=...)`，不是新开会话代替恢复。
- **事件与前端：**SSE 按持久事件 ID 回放，支持 `after` 与 `Last-Event-ID`；前端 hook 处理分帧、断线重连、重复事件过滤和缓存刷新。浏览器断连不会取消 Worker。
- **取消与异常：**取消设置持久标记，Worker 轮询取消执行；失败/取消/过期会让待审批失效。Chat 的失败、取消或 partial 会轮换 checkpoint，避免未完成工具周期影响下一轮。
- **数据职责：**业务表保存任务、来源、断言、审批和执行回执；`AsyncPostgresSaver` 保存图消息/中断；`AsyncPostgresStore` 跨会话读取偏好、观点和来源信任，按 namespace/key upsert，不使用向量检索。
- **可靠性范围：**advisory lock 限制同库一个 Worker；通用研究接口有 request_key 幂等，单帖入口没有同等跨刷新去重。外部只读请求在崩溃窗口可能重复，Store 与业务事务不是跨存储原子提交。
- **本人承担：**C02/C03/C05；将持久状态、取消与审批连续性作为任务要求，通过 AI 协作实现并结合历史恢复记录验收。
- **证据：**E07、E08、E10、E17。**属性：**IMPL + ACT-REC；本轮只重跑非数据库测试。

### M06｜人工审批、编辑拒绝与写入幂等

- **做了什么：**Chat 对四类写入提议暂停，由用户批准、编辑或拒绝后继续；研究模式不暴露这些写工具。
- **四类动作：**`add_to_watchlist`、`save_thesis`、`update_investment_preferences`、`update_source_trust`，分别写入关注标的、已有标的观点、风险/期限偏好、人工来源信任标签。
- **为什么：**模型提议不等于明确授权；“同意执行”不等于执行成功；拒绝、过期、重启和重复点击都应有一致行为。
- **关键实现：**HITL 把 interrupt_id/action_index/tool_call_id 与业务 Approval 对应；提交决定时锁 Run，编辑参数走对应 Pydantic schema，批量决定按原动作顺序恢复。默认有效期 72 小时，失效/取消不能再执行。
- **执行边界：**写工具再查已提交的 approved/edited、核对实际参数；使用 `run_id:tool_call_id` Operation key 返回既有结果；决定字段与 `execution_status` 分开，拒绝为 `not_executed`，执行异常为 failed。
- **结果：**真实 Qwen 写提议跨应用重启保留同一审批，拒绝后恢复且未执行；批准、编辑、动作顺序、重复提交等由隔离数据库/确定性模型测试验证，不是自动批准真实个人资料。
- **范围：**用户在明确表单中直接添加关注属于用户直接操作，不要求 Agent 审批。幂等控制不是任意外部系统或跨存储 exactly-once 保证，也不是多角色企业权限系统。
- **本人承担：**C02/C03/C05；坚持个人写入需人工控制，使用 AI 协作完成实现与验证；没有让测试自动批准真实个人资料。
- **证据：**E08、E10、E17。**属性：**IMPL + ACT-REC + 隔离测试。

### M07｜资源预算、外部错误与运行边界

- **做了什么：**Middleware 统计模型/工具/外部请求/token，限制搜索和抽取范围，记录安全事件，约束上下文与结果长度；HTTP 层处理缓存、限速、有限重试和结构化失败。
- **为什么：**开放式工具循环可能扩大研究范围、消耗预算或把失败包装成成功；必须先控制调用，再评价生成。
- **默认预算：**模型调用 14 次、工具调用 18 次、直接外部请求 30 次、累计 60,000 tokens、单次活动执行窗口 420 秒；普通 HTTP 超时 25 秒，模型超时 90 秒。这些是默认上限配置，不是实际平均消耗或金额成本。
- **收束设计：**研究超过默认收束轮次 4，或工具调用达到 8，或 token 达半额时，停止继续扩展读工具并要求用已取得资料输出；预算控制与缺失说明结合，不强行补全。
- **内容边界：**Tavily search 最多 5 条，extract 1—3 个公开 HTTPS URL；单次工具结果最多纳入 6 个文档，单片段至多 4,000 字符、合计至多 12,000 字符；保持模型和保存片段一致。
- **外部适配：**固定供应商 REST 路径、凭证由服务注入；HTTP 对只读网络失败及 429/部分 5xx 有限重试，并结合 Retry-After；过长等待或无权限明确不可用，不向用户持久化原始 SDK 异常中的地址或密钥。
- **安全边界：**默认本机监听；可配置应用访问令牌，检查未授权来源。外部文本被提示视为不可信数据；不给模型任意 HTTP/SQL 权限。URL 检查不是完整 DNS 隔离，提示约束不是注入攻击已全面解决的证明。
- **结果与限制：**历史首次研究曾因 token 耗尽无法形成报告，限制结果长度并加入收束后，受限 NVDA 案例完成。没有可比较的批量成本基线，不写“成本降低 X%”；token 为调用后累计的软阈值，不是金额硬封顶。
- **本人承担：**C02/C03；在 AI 协作联调中围绕范围、失败和成本边界完成调整。不能改写为本人自研安全沙箱或完整注入防御。
- **证据：**E04、E05、E07、E09、E10。**属性：**IMPL + 受限 ACT-REC。

## 六、供后续 AI 使用的规则

### 6.1 收到 JD 后的操作顺序

1. **提取岗位任务：**区分岗位要交付什么、面对谁、所需能力、工具与结果；不要只做关键词计数。
2. **建立匹配表：**为每项核心任务列出 `JD 任务 → K 编号 → M 模块 → E 证据 → Q 结果/B 素材 → 事实属性`。没有证据的要求标为缺口。
3. **判断是否选入：**能够支持至少一项核心任务且有具体工作/产出时优先；仅有背景兴趣或设计愿景时降低权重。结合其他项目比较，不能因本资料库较长而自动优先。
4. **选择角度与篇幅：**按 JD 的核心任务排序，通常用一句背景及 2—4 条工作/结果；选择最相关的技术或产品细节，而非照抄完整素材表。
5. **生成项目描述：**使用“工作动作＋解决问题/对象＋方法或关键取舍＋可核对产出”结构，保留单帖研究及证据复核主线。
6. **做事实检查：**逐条追溯到 E；确认 IMPL、ACT-REC、ACT-LOCAL、DESIGN、SIM 的类别，检查日期、样本、分母、单位、测试跳过和本人贡献。
7. **做岗位检查：**说明该条为何有助于目标岗位，删除不相关堆栈；对 JD 必须但项目没有的能力，不补造经历，也不以“了解”伪装完成过。

### 6.2 匹配强度的判断

| 匹配强度 | 判断条件 | 处理 |

| 部分对应 | 有相近能力，但缺场景、规模或验证，例如本地恢复与生产可靠性、审批与企业权限。 | 描述已经做过的部分，保留范围，不升级规模。 |
