# 架构与职责

本文说明当前代码的工程结构。产品目标与当前实现差异统一见 [产品技术交付附录](../ai-product-case/原稿/12-技术交付附录.md) 和 [Figma 设计说明](../ai-product-case/Figma设计/设计说明.md)。

## 边界与技术选择

FastAPI 接受任务并提供查询、SSE 和前端静态服务；独立 Worker 从业务库取队列任务。研究状态不绑定浏览器连接。PostgreSQL 同时承载业务表、LangGraph checkpoint、长期 Store，但它们不是一笔跨系统原子事务。

| 组件 | 项目中的具体职责 | 不承担的职责 |
|---|---|---|
| LangChain create_agent | 单 Agent 模型 / 工具循环；research 输出 ReportDraft，chat 普通对话及写入提议 | 不另建重复 LangGraph 编排图，不做多 Agent |
| Qwen / ChatOpenAI | 通过 DashScope 兼容接口理解文本、选工具、组织断言与报告 | 不作为行情数据库、事实权威或正确率保证 |
| Runtime / ToolRuntime | 注入 RunContext、tool_call_id、Store；身份和审批状态由程序提供 | 用户身份不是模型可填工具参数 |
| Middleware | 预算、事件、来源截断与捕获、工具错误、有限重试、HITL | 引文语义是否支持主张不由 Middleware 自动判定 |
| MCPAdapter / FastMCP | 将本地受限业务工具和 Tavily 远程工具接入同一 Agent 生命周期 | MCP 本身不保证数据真实、来源授权或写入安全 |
| AsyncPostgresSaver | 同一 checkpoint thread 的图状态、消息与 interrupt 恢复 | 不替代业务 Run / 审批表 |
| AsyncPostgresStore | 按用户 namespace/key 保存偏好、观点和信任标签，跨会话读取 | 无 embedding 或向量检索 |
| SQLAlchemy / Alembic | 业务事务、模型和迁移；Run、Source、Claim、Evidence、Approval、Operation 等 | 不把 UI 状态当执行成功 |
| APScheduler | 唯一 Worker 定时入队同步、站内简报和内容复核 | 停机期间不执行任务，不是外部推送系统 |

代码入口：[factory](../../backend/app/agent/factory.py)、[middleware](../../backend/app/agent/middleware.py)、[models](../../backend/app/models.py)、[worker](../../backend/app/worker.py)、[scheduler](../../backend/app/scheduler.py)。Python 顶层依赖见 [pyproject.toml](../../pyproject.toml)，实际版本见 [uv.lock](../../uv.lock)，前端见 [package-lock.json](../../frontend/package-lock.json)。LangChain MCP 接口锁定 beta 版本，升级需复测。

## 数据源契约

| 来源 | 接入方式 | 时间与口径 | 不可用时 |
|---|---|---|---|
| X | 本地 MCP → 官方用户 / 时间线 / 帖子 REST | ID 字符串、完整 note_tweet 文本、同步水位；初次回填有界，搜索默认关闭 | 记录错误，不推进未完成水位；撤回不可访问内容 |
| Massive | 本地 MCP → 官方 REST API key | 上一交易日 OHLCV、复权日线、公司资料；USD / as_of / session_date / is_realtime=false | 保留缺失状态，不补造价格；套餐 / 403 / 429 按返回处理 |
| SEC | 本地 MCP → submissions / concept / filing 原文 | CIK、unit、start/end、filed、form、accession；提交日不等于会计期间 | 自定义科目或文本缺失说明无法核查 |
| Tavily | 官方远程 MCP，Authorization 请求头 | 仅 search / extract；保存 URL、抓取时间和有限 excerpt | 连接失败或工具错误可使研究部分完成 |

Massive 的日线涨跌字段是同日 close 相对 open，不能表述为相对前日收盘涨跌。拥有 Massive key 不等于接通其托管 OAuth MCP；本项目实际采用本地 REST 包装。SEC 通过有联系身份的 User-Agent 访问，没有 SEC API key。

## 证据模型

每次 Run 保存 Source，模型只引用程序分配的 source_id。Claim 区分 fact、prediction、opinion、inference。Evidence 保留 stance（support / contradict / context）、quote 和 rationale。报告保存 summary、assessment、data_cutoff、uncertainties、coverage 等，便于界面分层阅读。

[reports.py](../../backend/app/reports.py) 将不存在的 source_id 和无法在本次 excerpt 中定位的引文移除并记录警告。X 证据只证明作者说过什么，不能独立支持投资事实；预测和意见转为 not_verifiable，支持与反对证据同时存在则 conflicting。不同域名 / 内容 hash 是描述性统计，不能当作独立信源数量或校准概率。

这些是来源与报告状态规则；时期、单位、主张覆盖和语义蕴含仍需人工或专项评估。评价方法见 [产品评估体系](../ai-product-case/原稿/08-评估体系与结果分析.md)。

## 存储与进程边界

业务表决定任务和审批状态；checkpoint 决定图的执行位置；Store 决定跨会话资料。写工具在业务事务内核对已提交审批和实际参数，记录 Operation；Store upsert 可能先于业务提交，依靠相同 namespace/key 恢复，不能声称跨存储 exactly-once。

Worker 使用 PostgreSQL advisory lock 保证同一数据库仅一实例；任务获取使用事务锁。HTTP 缓存和供应商限速也保存在 PostgreSQL。系统当前没有多租户认证和并发 Worker 调度承诺。
