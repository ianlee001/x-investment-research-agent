# 需求分析与版本规划

## 优先级原则

用“任务必要性、错误后果、使用频率、实现依赖”判断优先级。P0 是闭合核心任务或避免严重误导的必要条件；P1 提升持续使用；P2 扩展任务边界。不用缺乏真实样本的 RICE 分数制造精确感。

| 编号 | 功能与用户价值 | 优先级 | 页面 | 验收 |
|---|---|---|---|---|
| REQ-01 | 公开账号追踪：持续获得研究对象 | P0 | P02 | AC-01 |
| REQ-02 | 有界同步与混合帖子：保留选择权 | P0 | P02 | AC-02 |
| REQ-03 | 单帖核查与重复提交控制 | P0 | P02/P03 | AC-03 |
| REQ-04 | 原子断言与类型区分 | P0 | P03 | AC-04 |
| REQ-05 | 外部取证与时间单位口径 | P0 | P03/P04 | AC-05 |
| REQ-06 | 来源、引文、支持与反对证据 | P0 | P03 | AC-06 |
| REQ-07 | 分层报告与继续研究 | P0 | P03/P05 | AC-07 |
| REQ-08 | 异步任务、取消、重连与恢复 | P0 | P01/P03/P05 | AC-08 |
| REQ-09 | 关注标的与行情辅助 | P1 | P04 | AC-09 |
| REQ-10 | Agent 写入人工审批 | P0 | P05/P06 | AC-10 |
| REQ-11 | 设置与站内每日简报 | P1 | P01/P07 | AC-11 |
| REQ-12 | 可读性与跨设备操作 | P0 | 全部 | AC-12 |

## 方案取舍

手动选帖优先于全量自动核查，避免无关内容消耗预算。证据关系优先于更多来源数量，因为多个转载不能变成多份独立事实。报告详情采用渐进披露，摘要先行，第一条断言默认展开，来源和运行活动按需查看。行情保留为研究背景，清楚标注上一交易日收盘，避免“当前价”误导。

## 版本与进入条件

| 版本 | 范围 | 完成门槛 |
|---|---|---|
| V1 核心研究 | REQ-01—12，文本单帖、受限工具、审批、本地研究空间。 | P0 验收组无阻断缺陷；证据定位与预测类型规则通过；付费调用受预算控制。 |
| V1.1 任务连贯性 | 单帖请求去重、报告携带上下文追问、简报选取规则统一。 | 重复请求不新增活跃任务；刷新恢复；上下文标识可追踪；简报同一输入同一选取顺序。 |
| V2 阅读覆盖 | EXT-01 图片解析、EXT-02 观点周报、EXT-03 外部推送。 | 分别通过媒体获取与引用评估、观点聚类去重评估、订阅撤销与投递幂等验收。 |

迭代节奏按交付门槛推进：先闭合核心任务与阻断错误，再验证任务连贯性，最后按任务收益开放扩展。

## 需求变更规则

新增需求必须说明触发场景、现有替代方式、影响页面、数据与预算、验收案例。改变来源口径、审批动作或时间单位时，同步修改 PRD、原型、评价规则与追溯表。P0 缺陷优先于 P2 扩展；功能覆盖不能抵消关键误导。
